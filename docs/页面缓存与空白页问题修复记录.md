# 页面缓存与空白页问题修复记录

## 背景
- 问题：页面支持多开模块，左侧点击打开为内标签页。在多开场景下，切换到已打开内容时，所有模块内容偶发变为空白。
- 目标：
  - 修复切换空白问题，保障正常显示；
  - 建立更稳健的“不同模块页面切换时的缓存机制”。

---

## 根因分析（综合）
- 过渡与缓存的组合冲突：
  - 布局内容区采用 Transition(mode="out-in") + KeepAlive(include) + key=fullPath 的组合（早期实现），在页签切换瞬间，过渡会先卸载离场组件，再渲染进场组件；而 include 名单与 key 的动态变化可能引起 KeepAlive 裁剪缓存，导致短暂或持续“空白”。
- 缓存名单维度不一致：
  - include 名单按“组件名”匹配，key 却按 fullPath 切分实例，多实例/同名组件（如 BasicLibrary 的多子路由）易出现状态错配。
- 同名组件缓存误删：
  - 删除页签时按组件名直接从缓存名单删除，若存在多个同名视图实例，会误删其他页签的缓存。
- 组件名不显式：
  - 在构建后可能存在 name 不稳定，导致 keep-alive 匹配失效（风险项）。

---

## 第一次修复（稳定渲染与缓存基础）

### 修改点
1) 布局内容区渲染结构调整（移除 out-in 与 include 组合冲突）：
   - 位置：`src/layout/MainLayout.vue`
   - 关键变更：取消过渡 out-in 并简化为 keep-alive 包裹动态组件，初始版本将 key 调整为 `route.name` 以稳定复用。
   - 参考位置：[MainLayout.vue](file:///f:/CodeProject/PMC/PMCSystem_Front/pipe-rule-configurator_web/src/layout/MainLayout.vue#L96-L103)

2) 缓存名单删除逻辑优化（防止同名组件互相误删）：
   - 位置：`src/stores/tagsView.js`
   - 逻辑：`delView` 仅在 visitedViews 中不存在同名视图时才从 cachedViews 移除；`delOthersViews`/`delAllViews` 对 name 去重。
   - 参考位置：[tagsView.js](file:///f:/CodeProject/PMC/PMCSystem_Front/pipe-rule-configurator_web/src/stores/tagsView.js)

3) 显式设置视图组件名（保障 keep-alive 名称匹配稳定）：
   - 位置：`src/views/*.vue`
   - 涉及：`PmcCode.vue`、`DesignRuleConfig.vue`、`SpecConfig.vue`、`StandardSequence.vue`、`PropertyManagement.vue`、`BasicLibrary.vue`

### 效果
- 切换时不再出现“全白”；
- 缓存名单与视图对应关系更稳健。

---

## 第二次修复（新增基于路由 meta 的缓存机制）

### 机制说明
- 在布局层对缓存进行“分流渲染”：
  - 当路由 `meta.keepAlive === true`：通过 `<keep-alive>` 缓存渲染，key 使用 `route.fullPath` 支持同组件的多实例缓存；
  - 否则：直接渲染，不进入缓存。

### 修改点
1) 布局内容区分流实现：
   - 位置：`src/layout/MainLayout.vue`
   - 实现：在 `router-view` 插槽解构出 `route`，使用两个 `v-if` 分支分流渲染；缓存分支放入 `<keep-alive>` 内，非缓存分支单独渲染。
   - 参考位置：[MainLayout.vue](file:///f:/CodeProject/PMC/PMCSystem_Front/pipe-rule-configurator_web/src/layout/MainLayout.vue#L96-L103)

2) 为各模块子路由添加 `meta.keepAlive: true`：
   - 位置：`src/router/modules/*.js`
   - 涉及：`spec.js`、`pmc.js`、`design.js`、`property.js`、`standardsequence.js`、`library.js`（BasicLibrary 各专业子项）。

3) 清理布局中未使用的缓存引用（如已不再需要的 include 绑定）。

### 辅助修复（构建保障）
- 新增 `src/api/library.js` 最小 API 协议，满足 `BasicLibrary.vue` 的构建依赖。

### 效果
- 缓存控制更清晰：是否缓存取决于路由 `meta.keepAlive`；
- 多实例场景（相同组件不同路径）能独立缓存；
- 进一步降低切换空白的偶发风险。

---

## 验证
- 打开多个模块页签（PMC 编码、属性管理、标准简选、基础库各子项等），在不同页签之间来回切换：
  - 标记 `keepAlive: true` 的页面状态应被保留并快速恢复；
  - 非缓存页面不保留状态；
  - 无“切换后内容全空白”。
- 构建验证：`npm run build` 通过。

---

## 影响范围与兼容性
- 布局层渲染结构调整，仅影响页面切换行为，不影响页面内部逻辑；
- 路由配置新增 `meta.keepAlive`，可按需在特定页面关闭缓存（移除该字段即可）；
- 为视图设置 `name`，仅用于缓存识别，无业务副作用。

---

## 后续建议
- 如需限制缓存实例数（LRU），可在 `<keep-alive>` 增加 `:max`；
- 对特定页面需要“强制刷新”时，可在对应视图使用 `onActivated` 检测状态并拉取必要数据；
- 若部分页面存在内嵌子页签，建议使用相同的 meta 分流策略进行独立控制。

## 回滚指引（如需）
- 若需恢复旧行为：
  - 将布局中的分流渲染撤销，恢复原先简单 keep-alive 包裹（不建议）；
  - 或将相应路由移除 `meta.keepAlive`，使之不再缓存。
- 注意：不建议恢复 out-in + include 的组合，容易再次出现空白页。
